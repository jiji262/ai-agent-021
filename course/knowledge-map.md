# 知识地图（Knowledge Map）

> **定位**：本文件是本课程「知识领域」与「面试主题」的唯一权威源。
>
> **三件事**：
> 1. 系统列出本课覆盖的 AI Agent 知识领域，供读者纵览全貌、查漏补缺。
> 2. 定义一份**权威主题集**——所有面试题 `【主题：X】` 标注里的 `X` 必须取自这里，校验器 `validateQuestionMeta` 也以此为合法主题集。
> 3. 给出**主线节 → 知识领域映射表**——每个主线节（`02-what-is-agent.md`–`29-deploy-and-beyond.md`）至少映射一个知识领域，校验器 `checkKnowledgeMapCoverage` 据此判定覆盖完整性。
>
> **维护规则**：新增面试主题先在第二节「主题集」登记，再在题目里引用；新增章节先在第三节「映射表」补一行。两张表是脚本门禁的输入，改动需保持表格结构稳定。

## 一、知识领域清单

按学习阶段（入门 → 基建 → 核心 → 工程 → 进阶 → 演进）组织，对齐 `style-guide.md` §10.3 的架构演进顺序。每个领域后标注主要落点的标题节号。

### 入门篇 · 搞清楚 Agent 是什么

| 知识领域 | 一句话 | 主要落点 |
|---|---|---|
| Agent 与 Chatbot 的本质区别 | 一问一答 vs 感知-推理-行动闭环；能不能调工具、改世界状态 | 第 1 节 |
| Agent 进化史 | Chatbot → RAG → Tool-Calling → Autonomous 四代演进与分水岭 | 第 2 节 |
| ReAct 与规划范式 | Reasoning + Acting 交替循环，以及 Plan-Execute、Reflection 等规划模式 | 第 3 节 |
| Agent 系统架构 | 交互层 / 推理层 / 执行层 / 持久层的四层切分与职责边界 | 第 4 节 |

### 基建篇 · 把项目跑起来

## 五、覆盖校验说明（给校验器与作者）

- **主题合法性**：写章节内嵌面试题时，`【主题：X】` 的 `X` 必须逐字符等于第二节「主题」列中的某一项。`validateQuestionMeta(q, topics)` 用第二节主题集做判定，未登记主题判不合规。
- **核心主题全覆盖**：第四节列出的 13 个核心主题，每个都必须至少被一道面试题命中（需求 R3.7、覆盖校验）。
- **主线节全映射**：第三节映射表中每个主线节都至少有一个知识领域。`checkKnowledgeMapCoverage(mainlineChapters, mapping)` 通过当且仅当无任何主线节缺映射。
- **扩展须先登记**：要新增面试主题，先在第二节「主题集」加一行，再在题目里引用；要新增/调整章节，先在第三节映射表补行，保持文件号与标题节号映射（标题节号 = 文件号 − 1）。
